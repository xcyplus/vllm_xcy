# SlotOffload：面向结构化提示词的价值感知 KV Cache 分层卸载

> 中文投稿初稿，版本：2026-06-23  
> 作者、单位、基金、会议模板和最终实验数字待补充。文中“初步结果”来自现有单种子实验，不能直接作为最终投稿结果。

## 摘要

大语言模型在线服务通常使用前缀缓存复用重复提示词的 Key-Value（KV）状态，并在 GPU 显存不足时将 KV Cache 卸载到 CPU 内存。然而，现有卸载策略通常将已完成的 KV 块视为同质对象，忽略了业务提示词内部“共享模板”和“实例变量”在复用价值上的显著差异。因此，大量只出现一次或难以再次命中的个性化 KV 块仍会占用 CPU 缓存容量和 PCIe 带宽，并可能挤出真正高价值的共享前缀。

本文提出 SlotOffload，一种面向结构化业务提示词的价值感知 KV Cache 卸载准入机制。SlotOffload 由应用在组装提示词时附加轻量级 token 区间元数据，将提示词划分为指令、模式、上下文和实例槽位等片段；随后在 vLLM 的块级卸载路径中联合考虑块内共享 token 比例、带时间衰减的历史热度、预填充重算与双向传输代价，以及 CPU 缓存实时压力，动态决定每个 KV 块是否值得写入 CPU。该机制只改变卸载准入，不改变注意力计算、GPU KV 分配和前缀哈希匹配语义，因此不会影响模型输出正确性，并且对未携带结构元数据的请求保持原生行为。

我们在 vLLM 中实现 SlotOffload，并构建覆盖金融、客服、医疗、供应链和内容安全等 16 类模板的可重复基准。初步单种子结果表明，在 Qwen2.5-0.5B 和 3B 的受控缓存工作集上，价值感知策略相对原生卸载减少约 92% 的 CPU 写入流量，同时保留约 98%--103% 的外部前缀命中 token；其时延收益取决于模型规模、访问分布和传输开销。完整实验将进一步从模型规模、缓存工作集比例、模板频率和复用距离四个维度验证方法的适用边界。

**关键词：** 大语言模型推理；KV Cache；前缀缓存；分层内存；缓存准入；vLLM

## 1 引言

前缀复用是降低大语言模型首 token 时延（Time To First Token，TTFT）的重要手段。在客服工单、信贷审核、医疗报告分析和作业批改等在线业务中，同一模型会反复处理由固定系统指令、业务规则、输入字段定义和用户实例值拼接而成的提示词。只要前缀 token 完全一致，服务系统就可以直接复用对应 KV Cache，避免重复执行预填充计算。

GPU 显存容量限制了可保留的 KV 块数量。vLLM 等系统因此支持将 GPU 中的 KV 块卸载到 CPU 内存，并在后续请求命中时加载回 GPU。该机制扩大了逻辑缓存容量，但也引入了两个新问题。第一，GPU 到 CPU 的写入并非免费；对于不会再次访问的块，写入本身就是纯开销。第二，CPU 缓存同样有限，低价值块可能挤出高复用共享前缀，导致后续请求重新计算或产生额外的数据搬运。

我们观察到，结构化业务提示词中的 KV 块具有明显不同的复用价值。固定指令、字段模式和输出规范在同一模板的请求之间保持不变，而姓名、年龄、血糖、订单号等实例槽位通常随请求变化。简单地“保存所有完成块”无法利用这一先验；简单地“只保存模板、不保存槽位”又无法处理块边界混合、模板冷热差异和缓存压力变化。例如，一个 16-token KV 块可能同时包含 12 个字段定义 token 和 4 个用户值 token，它仍可能是值得保存的共享块；一个纯模板块如果只出现一次，也不值得承担卸载成本。

为此，本文提出 SlotOffload。其核心思想不是预测模型注意力，也不是改变 KV 内容，而是在发生 CPU 卸载之前回答一个系统问题：**在当前结构、历史访问和缓存压力下，这个 KV 块未来带来的预填充节省是否足以覆盖存取代价？** SlotOffload 将应用可知的提示词结构传递给推理引擎，并在块级准入阶段计算价值分数。方法包含四个相互配合的部分：精确块内结构比例、衰减访问热度、计算与传输收益估计，以及压力自适应阈值。

本文的主要贡献如下：

1. 提出一种应用辅助的结构化提示词表示，将业务模板中的共享片段和实例槽位映射为 token 区间，使卸载策略能够识别同一物理 KV 块内的混合组成。
2. 设计一种价值感知的 KV 卸载准入策略，联合结构、热度、重算收益和 CPU 缓存压力，并通过冷块、槽位占比和负收益三类快速门控减少无效写入。
3. 在 vLLM V1 的 OffloadingConnector 中完成非侵入式实现。该实现只过滤 STORE 操作，对无元数据请求回退到原生行为，并提供逐块决策日志和 Prometheus 指标。
4. 构建多场景、可控制模板频率与复用距离的实验框架。初步结果显示该方法能显著减少卸载写流量，同时维持大部分外部前缀命中；完整实验将系统揭示其收益条件和性能边界。

## 2 背景与动机

### 2.1 KV Cache 与前缀复用

Transformer 自回归推理分为预填充和解码两个阶段。预填充阶段处理全部输入 token，并为各层生成 Key 和 Value；解码阶段逐 token 生成输出。对模型、适配器、token 序列和相关执行配置均相同的前缀，其 KV Cache 可以安全复用。

vLLM 使用 PagedAttention 将 KV Cache 划分为固定 token 数的块，并借助块哈希识别可复用前缀。一次请求只能从第一个 token 开始连续命中；如果中间某个块不同，该块之后的缓存即使内容相似也不能作为该请求的连续前缀直接加载。因此，业务提示词应将稳定共享内容放在个性化值之前。

### 2.2 CPU 卸载的机会与代价

设一个 KV 块包含 \(B\) 个 token，占用 \(K_b\) 字节。将其写入 CPU 和从 CPU 读回 GPU 的时间近似为

\[
T_s(b)=\frac{K_b}{BW_{g2c}}, \qquad
T_l(b)=\frac{K_b}{BW_{c2g}},
\]

其中 \(BW_{g2c}\) 和 \(BW_{c2g}\) 分别表示 GPU 到 CPU、CPU 到 GPU 的有效带宽。若该块未来被复用，则可避免一次对应 token 的预填充计算；若永不复用，系统只付出 \(T_s\) 并占用 CPU 空间。模型越大、预填充越昂贵，复用的潜在收益通常越高；KV 表示越大或总线越慢，传输成本则越高。

### 2.3 结构化提示词中的价值差异

一个典型业务请求可写为

\[
P = P_{sys} \Vert P_{inst} \Vert P_{schema} \Vert P_{slot},
\]

其中 \(P_{sys}\) 为系统角色，\(P_{inst}\) 为业务规则，\(P_{schema}\) 为字段与输出格式，\(P_{slot}\) 为本次用户或业务实例值。前三部分通常在模板内部共享，最后一部分通常个性化。

仅使用二元块标签存在两个不足。首先，token 化和固定块边界会产生混合块；只要块与槽位相交就丢弃，会损失仍包含大量共享 token 的块。其次，“共享”不等于“会再次使用”：长尾模板、一次性模板和访问间隔很长的模板仍可能污染 CPU 缓存。因此，需要同时建模静态结构价值和动态复用价值。

### 2.4 设计目标

SlotOffload 遵循四个目标：

- **有效性：** 减少无复用收益的 GPU 到 CPU 写入，并提高单位 CPU 容量带来的命中收益。
- **自适应性：** 根据模板频率、复用距离、模型计算成本和 CPU 缓存压力改变准入决策。
- **正确性：** 不近似、不裁剪 KV，不改变模型注意力计算和输出。
- **兼容性：** 结构元数据可选；没有元数据的普通请求保持 vLLM 原生卸载行为。

## 3 SlotOffload 设计

### 3.1 应用辅助的提示词结构标注

SlotOffload 不使用额外神经网络识别槽位。业务应用本来就需要将系统指令、模板和用户字段组装为最终 prompt，因此可在同一过程中为各片段附加类型。当前实现支持 `system`、`instruction`、`template`、`schema`、`context` 和 `slot` 等类型。

应用调用与模型 tokenizer 一致的编码器，按拼接顺序计算每个片段的 token 起止位置，并将元数据随请求放入 `kv_transfer_params["slot_offload"]`。例如：

```json
{
  "slot_offload": {
    "instruction_ranges": [[0, 48]],
    "schema_ranges": [[48, 96]],
    "slot_ranges": [[96, 128]]
  }
}
```

该表示不要求用户以 JSON 形式提问。结构化表单、数据库记录或自然语言输入可先经过业务应用的既有解析流程，再由模板引擎生成最终提示词和区间元数据。本文研究的是模板已知的在线服务场景；完全开放的无模板对话不属于当前方法的主要目标。

### 3.2 块内结构价值

设卸载块 \(b\) 包含 \(B\) 个 token，类型 \(k\) 的 token 数为 \(n_{b,k}\)。槽位比例和共享比例分别为

\[
r_{slot}(b)=\frac{n_{b,slot}}{B}, \qquad
r_{shared}(b)=1-r_{slot}(b).
\]

SlotOffload 为不同共享类型设置权重 \(w_k\)，并对槽位设置惩罚 \(\lambda\)，得到结构分数

\[
S(b)=\operatorname{clip}\left(
\sum_{k \ne slot} w_k\frac{n_{b,k}}{B}
-\lambda r_{slot}(b), 0, 1\right).
\]

相比粗粒度二元标签，该分数能保留以共享 schema 为主、仅在边界包含少量槽位 token 的混合块。默认情况下，指令、模板和系统片段权重为 1.0，schema 为 0.9，上下文为 0.7，槽位惩罚为 1.0。

### 3.3 带复用距离衰减的热度

SlotOffload 为每个卸载块哈希维护轻量级历史项。第 \(t\) 次观察块 \(b\) 时，设距上次观察经过 \(\Delta_t\) 个块事件，其衰减计数更新为

\[
c_t(b)=c_{t-1}(b)e^{-\gamma\Delta_t}+1,
\]

其中 \(\gamma\) 是衰减系数。热度分数为

\[
H(b)=\min\left(1,\frac{c_t(b)}{C_{sat}}\right),
\]

其中 \(C_{sat}\) 为热度饱和阈值。该设计使访问次数相同但复用距离不同的块获得不同分数：短时间内重复出现的模板更容易被准入，长时间未访问的模板逐渐降温。历史表使用有序映射并设置最大条目数，避免跟踪状态无限增长。

### 3.4 计算与传输收益估计

仅凭热度无法区分“复用一次是否值得”。SlotOffload 用累计访问次数 \(a_b\) 估计复用概率：

\[
P_r(b)=\frac{a_b}{a_b+\eta},
\]

其中 \(\eta\) 是平滑系数。设每 token 预填充时间估计为 \(t_p\)，则一个块的重算时间为

\[
T_r(b)=B\cdot t_p.
\]

块的期望净收益为

\[
G(b)=P_r(b)T_r(b)-T_s(b)-P_r(b)T_l(b).
\]

代价分数归一化为

\[
C(b)=\operatorname{clip}\left(\frac{G(b)}{T_r(b)},0,1\right).
\]

当 \(G(b)<0\) 时，即使块具有共享结构，策略也直接拒绝写入。当前原型允许通过配置传入每 token 预填充时间和双向带宽。最终版本将增加启动阶段微基准或在线指数滑动平均，降低手工配置误差。

### 3.5 压力自适应准入

综合价值分数为

\[
V(b)=\alpha S(b)+\beta H(b)+\delta C(b),
\]

其中默认 \(\alpha=0.5\)、\(\beta=0.3\)、\(\delta=0.2\)。设 CPU 缓存使用率为 \(q\in[0,1]\)，动态准入阈值为

\[
\theta(q)=\min(1,\theta_0+\mu q),
\]

其中 \(\theta_0\) 为基础阈值，\(\mu\) 为压力系数。缓存空闲时，系统允许更多候选块进入；缓存接近满载时，只有高价值块能够写入，从而减少低价值数据对有限 CPU 容量的污染。

最终决策按以下顺序执行：

1. 若请求没有结构元数据，则保持原生 STORE 行为。
2. 若槽位比例超过 \(r_{max}\)，则拒绝该块。
3. 若累计访问次数少于 \(a_{min}\)，则将其视为冷块并拒绝。
4. 若期望净收益 \(G(b)<0\)，则拒绝该块。
5. 否则，仅当 \(V(b)\ge\theta(q)\) 时写入 CPU 缓存。

这几个快速门控不仅减少计算，也使策略更容易解释。日志会为每个决策输出 `slot_ratio`、`accesses`、`benefit_us`、`pressure`、`value`、`threshold` 和拒绝原因。

### 3.6 正确性与回退

SlotOffload 只控制某个已完成 KV 块是否复制到 CPU。被拒绝的块仍可暂时保留在 GPU 中，之后也可能按 vLLM 原有策略被淘汰；若后续请求无法命中，它将正常重新执行预填充。被准入的块内容没有经过近似、量化或裁剪，并且仍由 vLLM 的精确前缀哈希验证。因此，SlotOffload 影响性能和缓存命中，不影响模型语义。

## 4 vLLM 实现

### 4.1 总体路径

原型基于 vLLM V1 OffloadingConnector 实现。请求进入服务后，应用侧构造器生成 prompt 和 token 区间元数据；调度器在一个完整 offload block 可写入时查询 CPU 缓存压力并调用准入策略；准入通过的块进入原有 TransferJob，未通过的块跳过 CPU STORE。

```text
业务字段/自然语言输入
        |
        v
模板组装 + tokenizer 区间标注
        |
        v
vLLM 请求与 kv_transfer_params
        |
        v
块完成 -> 结构/热度/代价/压力评分
        |                       |
      STORE                   SKIP
        |                       |
   原生 CPU offload       保持原生 GPU 生命周期
```

### 4.2 主要模块

- `vllm/entrypoints/slot_offload_prompt.py`：将带类型的 prompt 片段转换为文本和 token ranges。
- `vllm/distributed/kv_transfer/kv_connector/v1/offloading/slot_policy.py`：解析配置、计算块内结构、维护热度并生成准入决策。
- `vllm/distributed/kv_transfer/kv_connector/v1/offloading/scheduler.py`：在创建 STORE job 前接入策略，并读取实时 CPU 缓存使用率。
- `benchmarks/slot_offload_benchmark.py`：生成多场景模板负载、控制访问分布并采集请求与缓存指标。
- `benchmarks/summarize_slot_offload_experiments.py`：按模型、工作集、并发和策略聚合多随机种子结果。

### 4.3 复杂度

对每个候选块，结构统计最多扫描 \(B\) 个标签，因 vLLM offload block 大小固定且较小，可视为 \(O(1)\)。热度表的有序映射查询和更新平均为 \(O(1)\)，内存复杂度为 \(O(N_h)\)，其中 \(N_h\) 由 `slot_offload_max_tracker_size` 限制。策略不增加 GPU kernel，也不修改 KV 数据格式。

## 5 实验设计与初步结果

### 5.1 研究问题

实验围绕以下问题展开：

- **RQ1：** SlotOffload 能否减少 CPU 写入和双向传输，同时保持有价值的前缀命中？
- **RQ2：** 减少写入是否能转化为 TTFT、尾时延和吞吐收益？收益在何种模型和负载下成立？
- **RQ3：** 结构、热度、收益估计和压力阈值各自贡献多少？
- **RQ4：** 模型规模 \(M\)、GPU 工作集比例 \(\rho_g\)、模板频率 \(p_i\) 和复用距离 \(D_i\) 如何影响策略？
- **RQ5：** 策略本身的 CPU 时间、跟踪表内存和请求元数据开销有多大？

### 5.2 实验环境

最终稿应完整报告 CPU 型号与核心数、内存容量与频率、GPU 型号与显存、PCIe 代际、CUDA/PyTorch/vLLM 版本、操作系统、模型精度和模型来源。计划在单张 48 GiB GPU 上测试 Qwen2.5-0.5B、3B 和 7B。为隔离模型规模，每个模型使用校准后的 `--kv-cache-memory-bytes`，保证 GPU 可容纳的 KV token 数近似相同；CPU 缓存容量按 GPU token 容量的固定倍数设置。

由于当前 1024-token 配置产生的预填充时间较短、测量噪声较大，最终主实验计划将受控容量提高到 4096 或 8192 token，并同步扩展模板长度和工作集，使 \(\rho_g\) 仍覆盖 0.5、1、2 和 4。1024-token 结果仅用于功能验证和高压力微基准。

### 5.3 工作负载

基准包含 16 类现实结构模板，包括个人贷款、房贷审核、信用卡额度、小微企业贷款、交易反欺诈、保险核保、健康筛查、客服工单、供应商风险、合同合规、作业批改、安全告警、员工流失、物流异常、内容审核和预测性维护。每类模板具有固定角色、规则、输入 schema 和输出 schema，实例槽位随请求变化。

访问序列支持以下分布：

- `uniform`：各模板近似等频，观察没有明显热点时的行为。
- `zipf`：模拟少数热门模板和大量长尾模板。
- `one_hit`：部分模板只出现一次，直接检验无效写入过滤能力。
- `reuse_short/medium/long`：保持各模板总频率相同，只改变平均复用距离，隔离 \(D_i\) 的作用。

定义共享模板工作集 token 数为 \(W\)，GPU 和 CPU 容量分别为 \(C_g\) 与 \(C_c\)，则

\[
\rho_g=\frac{W}{C_g}, \qquad \rho_c=\frac{W}{C_c}.
\]

当 \(\rho_g>1\) 时，GPU 无法同时容纳全部模板前缀，CPU 卸载才具有明确机会；改变 \(\rho_c\) 可验证压力自适应阈值。

### 5.4 对比方法

- **GPU-only：** 只使用 vLLM GPU 前缀缓存，不启用 CPU offload。
- **Native：** 原生 OffloadingConnector，保存所有满足原生条件的块。
- **Store-threshold：** vLLM 基于访问次数阈值的卸载基线。
- **Binary Slot：** 只按粗粒度类型保留共享块、过滤 slot 块。
- **SlotOffload：** 本文完整的结构与价值感知策略。

最终相关工作对比需要谨慎区分：SWARM 和 SolidAttention 主要针对 SSD 层与 I/O 调度，KVShare 和 CacheSlide 的目标与复用粒度也不同。若其源码、硬件需求或 vLLM 版本无法公平复现，应在论文中做定性比较，而不伪造端到端数字。

### 5.5 指标

主要指标包括平均/P95/P99 TTFT、请求吞吐、GPU 到 CPU STORE 字节、CPU 到 GPU LOAD 字节、STORE/LOAD 时间、外部前缀命中 token、命中保留率，以及单位 STORE MiB 获得的命中 token。系统开销实验还需增加每次准入决策耗时、跟踪表条目数、元数据字节数和 CPU 占用。

其中两个关键效率指标为

\[
R_{store}=1-\frac{Bytes_{ours}}{Bytes_{native}},
\]

\[
E_{cache}=\frac{HitTokens}{StoreMiB}.
\]

只报告“写入减少”是不充分的，因为一个永不缓存的策略也能减少 100% 写入。必须同时报告命中保留率、TTFT 和 \(E_{cache}\)。

### 5.6 初步结果

表 1 汇总现有 256 请求、并发 1、单随机种子结果。GPU KV 容量约为 1024 token，CPU 容量约为其 4 倍。该结果用于确认机制可运行和发现实验问题，不用于最终显著性结论。

**表 1：现有单种子预实验中 SlotOffload 相对 Native 的结果**

| 模型 | 分布 | TTFT 变化 | STORE 减少 | 外部命中保留 |
| --- | ---: | ---: | ---: | ---: |
| Qwen2.5-0.5B | one-hit | 改善 15.69% | 93.09% | 100.00% |
| Qwen2.5-0.5B | uniform | 改善 25.04% | 92.40% | 97.56% |
| Qwen2.5-0.5B | Zipf | 改善 20.70% | 92.92% | 102.53% |
| Qwen2.5-3B | one-hit | 下降 15.98% | 93.07% | 100.00% |
| Qwen2.5-3B | uniform | 下降 0.04% | 92.40% | 97.56% |
| Qwen2.5-3B | Zipf | 下降 1.29% | 92.92% | 102.53% |

预实验支持两个结论。第一，结构与价值准入稳定地过滤了约 92%--93% 的写入，并保留了大部分甚至更多外部命中 token，说明原生策略写入了大量未产生后续命中的块。命中保留超过 100% 并非错误：在有限 CPU 容量下，过滤低价值块可避免高价值块被挤出。第二，传输减少并不必然改善 TTFT。0.5B 上观察到明显改善，而 3B 的部分负载持平或退化，可能由单种子噪声、CPU 加载成本、当前静态代价参数和短 prompt 导致。该现象正是最终实验需要解释的边界，而不应被删除。

## 6 相关工作

### 6.1 LLM KV Cache 管理

vLLM 通过 PagedAttention 缓解 KV Cache 内部碎片并提高批处理效率，是本文实现的基础。后续工作从跨请求共享、跨实例传输、预填充/解码解耦和多级存储等角度扩大 KV 复用范围。Mooncake 以 KV Cache 为中心组织解耦式推理基础设施；LMCache 等系统支持在 GPU、CPU 及远端存储间复用 KV 状态。SlotOffload 与这些工作正交：它不改变 KV 的放置后端，而是在 CPU 写入前判断一个块是否值得进入下一层。

### 6.2 语义与结构感知复用

KVShare 研究语义感知的 KV Cache 共享，CacheBlend 等工作尝试复用非连续或不同上下文中的已计算 KV。CacheSlide 关注提示词中不变段与动态段的复用。与这些工作相比，SlotOffload 不放宽“token 前缀完全一致”的正确性条件，也不重新计算或融合不同上下文的 KV；它利用应用已知结构优化分层缓存准入。因此，其实现更轻量，但适用范围主要是模板化请求。

### 6.3 分层与存储卸载

SolidAttention 和 SWARM 探索基于 SSD 的 KV Cache 服务，重点解决设备带宽、并行 I/O、放置和协同激活等问题。本文聚焦单机 GPU--CPU 两级路径，不涉及 SSD。CPU 的时延和带宽特征与 SSD 不同，但二者共享一个基本问题：无差别写入会浪费下层容量和传输带宽。SlotOffload 的价值准入可作为未来多级存储放置策略的上游信号。

### 6.4 与传统缓存准入的关系

传统缓存系统常依据访问频率、最近性、对象大小或获取代价执行准入和淘汰。SlotOffload 借鉴这一思想，但加入了 LLM 业务提示词特有的 token 结构价值，并使用预填充重算成本与 KV 双向传输成本构造收益项。本文关注的是“是否写入 CPU”的 admission，而非替换 vLLM CPU 后端已有的 eviction 机制。

## 7 讨论与局限性

**结构元数据依赖。** 当前方法要求应用在 prompt 组装时提供片段类型。对模板平台、表单业务和 agent 工作流，这类信息天然存在；对完全开放的聊天请求，标注成本可能超过收益。未来可从 Jinja/chat template、函数调用 schema 或 prompt DAG 自动导出元数据，而不必训练 token 分类网络。

**精确前缀限制。** SlotOffload 不能跨越不同 slot 继续复用后续相同片段。因此，共享内容应尽量放在个性化值之前。解决非前缀共享需要位置修正、局部重算或注意力融合，属于另一类问题，也会显著增加两天原型和小论文的实现风险。

**代价模型精度。** 当前实现使用配置的每 token 预填充时间和带宽。真实系统的预填充成本受模型、批大小、序列长度和 GPU 状态影响。最终版本应增加在线校准，并比较静态估计与在线估计的误差。

**准入而非淘汰。** SlotOffload 当前控制写入，不直接选择 CPU 缓存满时淘汰哪个已存块。压力阈值能间接减少污染，但“价值感知准入 + 价值感知淘汰”可能进一步提升性能。

**未使用压缩。** CPU 侧 KV 量化或压缩能扩大容量，但可能引入压缩开销和数值误差。为保持当前论文贡献与实现一致，本文不将其作为已完成机制。后续可仅对高价值但体积较大的块采用选择性压缩，并独立评估准确性。

**实验外部有效性。** 合成调度序列可以精确控制频率和复用距离，但不完全代表生产流量。最终稿应增加一组脱敏真实 trace，或基于公开请求 trace 映射模板 ID，验证结论不依赖人工分布。

## 8 结论

本文提出 SlotOffload，一种面向结构化提示词的价值感知 KV Cache CPU 卸载准入机制。其基本出发点是：可复用的共享模板和难以复用的实例槽位不应被同等对待，而结构信息也不能替代动态访问和系统代价。SlotOffload 通过块内结构比例、衰减热度、计算/传输收益和缓存压力联合决策，在不改变模型计算语义的前提下减少低价值 CPU 写入。vLLM 原型和初步结果表明，该方法能够以较少写入保留大部分外部前缀命中；后续完整实验将进一步验证其时延收益、模型规模效应和工作负载边界。
